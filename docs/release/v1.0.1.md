# ReadMe v1.0.1 发布说明

> 发布日期：2026-11-11
> 适用版本：`1.0.1`
> 运行环境：Windows 10/11、WebView2；源码开发需要 Python 3.11.9；Edge TTS 联网

## 本版定位

`v1.0.1` 是 **v1.0.0 的排障补丁版**，不新增功能、不改动任何交互与数据口径。全部改动都是日志，用于定位「抖音直播间接不上」这一类现场问题。

## 版本内容

- **抖音短链解析留痕**：记录每次解析的结果与来源，区分两种情况
  - `抖音短链解析成功：web_rid=…（来源=reflow 页面，页面 N 字节）`
  - `抖音短链解析：reflow 页面未找到 webRid，回退按链接取号 -> web_rid=…（页面 N 字节，final=…）`
- **抖音房间接口失败留痕**：空响应 / 非 200 / 超时 / 非 JSON / 接口异常 / 直播间不存在 六类失败，全部带上当次的 `web_rid`、HTTP 状态、ttwid 与 Cookie 的有无。
- **连接成功留痕**：`已连接` 一行补充来源平台与原始输入 `room_key`，便于把日志行和界面输入对应起来。

## 排查口径

日志按「先解析、后请求」两段出现，据此可直接区分两类故障：

| 日志表现 | 结论 |
| --- | --- |
| 有 `解析成功`，随后 `房间接口返回空响应` | 房间号正确，卡在平台接口请求（网络出口、DNS 或风控） |
| 有 `解析成功`，随后 `直播间不存在` | 解析拿到了与当前直播不一致的号（平台页面数据延迟） |
| 只有 `回退按链接取号`，随后报错 | 分享页未返回渲染数据，回退逻辑拿到了内部 room_id |

## 支持平台

- **B 站**：完整链路支持。公开弹幕、登录态、朗读、浮窗、独立监看、历史场次、趋势/对比/复盘与 JSON/CSV 导出。
- **抖音**：支持公开弹幕、账号登录、礼物/入场解析和历史隔离；礼物按 `单颗钻石 × 数量` 累计为本机钻石流水，不折人民币、不代表平台结算。抖音没有 SC/舰长等价能力，相关界面和报告明确显示“平台未提供”，不伪造 `¥0.00`。

## 已知限制

- Edge TTS 依赖微软在线服务，断网无法合成；不是完全离线工具。
- 抖音短链解析依赖分享页返回的渲染数据，该数据由平台侧动态下发，个别时刻可能缺失；缺失时会回退按链接中的数字取号，取到的可能是内部 room_id 而非 `web_rid`，此时连接会失败并在日志中留下 `回退按链接取号` 字样。
- 抖音匿名状态下的部分礼物推送可能受平台风控影响。
- 抖音礼物按钻石累计，平台金额口径不与 B 站人民币字段混算。
- 在线人数、平台营收和观众活跃率不纳入计算；历史只保存本机聚合数据，不保存弹幕正文、用户名或 UID。
- 高密度弹幕会按队列上限丢弃最旧条目；这是有界降级，不代表收到全量消息。
- 浮窗、监看和主工作台的多显示器布局受 Windows DPI 与窗口捕获软件影响，首次使用需在本机确认位置。

## 安装与升级

### 便携包

1. 下载 `ReadMe-v1.0.1-standalone.zip` 并解压到任意目录。
2. 双击 `ReadMe.exe`。不需要安装 Python、pip 或 `.venv`。
3. 需要 Windows 10/11 和 WebView2；语音合成需要联网。

### 覆盖安装

`v1.0.1` 与 `v1.0.0` 的配置 schema、历史库 schema 完全一致，可直接覆盖安装，无需迁移。

升级前仍建议成对备份：

- `config.json`
- `config.legacy.json`
- `data/history.sqlite3`（如存在）

旧配置首次启动会在校验通过后迁移；迁移或写盘失败时进入只读安全模式，不覆盖原文件。

## 回滚

1. 关闭 ReadMe，确认主窗口、监看窗口和浮窗进程均已退出。
2. 直接重新安装 `v1.0.0` 即可；两者数据格式一致，不需要降级处理。
3. 如遇异常，成对恢复升级前的 `config.json` 与 `config.legacy.json`，再恢复对应的历史库备份。
