# ReadMe · 直播工作台

![ReadMe](assets/brand/readme-lockup-horizontal.svg)

> 当前版本：**v1.0.1** · [下载](https://github.com/raven-moonfade/readme-live-workspace/releases/latest) · [发布说明](docs/release/v1.0.1.md)

B 站 / 抖音直播弹幕实时语音朗读工具。输入直播间号或抖音直播间链接，即可把弹幕、礼物、入场消息实时转成语音播报；桌面工作台支持晨光 / 夜航 / 跟随系统主题。

## 下载

前往 [Releases](https://github.com/raven-moonfade/readme-live-workspace/releases/latest) 下载最新的 `ReadMe-v1.0.1-standalone.zip`，解压后双击 `ReadMe.exe`。**不需要安装 Python、pip 或 `.venv`。**

运行环境：Windows 10/11、WebView2；语音合成需要联网。

## 功能

- 实时读取 B 站直播弹幕（WebSocket，断线自动重连）
- 实验性读取抖音公开弹幕（网页端短轮询，支持直播间号与分享链接）
- 抖音账号登录：独立 WebView2 登录窗口，Cookie 使用 Windows DPAPI 加密保存；DPAPI 不可用时退化为带提示的 `plain1:` 可逆编码
- **四视图工作台**：左侧导航切换弹幕 / 弹幕工作台 / 数据 / 设置；跨页直播状态条始终显示队列、当前朗读和最近日志
- 五类消息独立开关：弹幕 / 礼物 / 醒目留言 / 上舰 / 入场
- 音色 / 语速 / 音调 / 音量 可调，内置 300+ 音色（Edge TTS，免费无 Key）
- 过滤规则：屏蔽词（一行一个）、同内容去重、单用户冷却、全局冷却、最长长度截断
- 朗读队列管理（可设上限，满了丢最旧）、每条弹幕可点「重播」
- 试听功能：输入任意文本立即合成播放
- 统计面板：收到 / 已朗读 / 丢弃 / 队列长度
- B 站账号扫码登录：登录后弹幕用户名不再打码（`月***` → 完整昵称）、按真实 UID 冷却
- **直播浮窗**：独立透明置顶窗口，可自定义宽高/位置/字体/字号/行高/颜色/背景透明度/描边/投影/行数/间距/停留时长/动画/对齐，支持四套主题、五类消息独立动效与鼠标穿透，可用 OBS、Streamlabs、直播伴侣等窗口捕获
- **礼物答谢置顶/置底**：弹幕密集时把礼物单独固定在浮窗顶部或底部（停留时长、条数、最低价值均可调），同一用户同一礼物自动合并数量
- **模拟数据调试**：在「弹幕工作台 → 调试」里一键注入弹幕/礼物/SC/上舰/入场（可连发、可弹幕风暴），用于调试浮窗排版与朗读效果，无需开播
- **六层浮窗预设**：内容 / 样式 / 布局 / 动画 / 模板 / 预设包；支持 JSON 预设包导入导出、逐层应用与原生模板 `bubble / compact / focus`
- **弹幕工作台页**：完整内嵌浮窗样式、预设、规则、窗口与调试工作台，跟随晨光 / 夜航主题；页头显示浮窗当前状态，监看入口统一保留在顶部工具栏
- **监看窗口**：小 / 中 / 大 / 超大四套界面预设，分别调整顶栏、工具条、行高、字段布局和阅读字号；`Ctrl+滚轮` 可循环切换
- **数据页**：本场实时脉冲台 + 本场账本 + 运行提示 + 本机历史场次；历史支持标题/房间号搜索、日期与平台筛选、cursor 分页、单房间按小时/日/周趋势、同房间上一场 / 任意基准场 / 多基准场（最多 3 个）对比与分析报告导出、JSON / CSV 导出、手动安全清理与可关闭的启动自动清理，只展示后端场次统计与本机事件流能证明的数据，模拟事件单独隔离
- **事实型复盘**：历史详情展示同房间最近 20 场的本机观测基线、收到/小时名次、观测四分位区间和记录内 5 分钟消息峰值；样本不足或数据不完整时明确降级，不做因果推断、健康分或平台观众/营收判断

## 快速开始

1. 解压 `ReadMe-v1.0.1-standalone.zip` 后双击 `ReadMe.exe`
2. 顶部选择「B 站」或「抖音」，输入直播间号；抖音也支持 `live.douyin.com/...` / `v.douyin.com/...` 链接
3. 点「连接」；弹幕开始朗读

> 首次启动会自动生成 `config.json`、`logs\`、`cache\`。
> 若项目路径过深，PySide6 安装可能受 Windows 260 字符路径限制；建议放在 `D:\ReadMe` 这类短路径，或开启 Windows 长路径支持。


## 主题外观

顶部「外观」按钮提供两套预设：

- **广播校样**：信号橙、无点阵、直角、广播窄体。
- **钴蓝点阵**：钴蓝、24px 点阵、圆角、系统无衬线。

明暗模式提供 **晨光 / 夜航 / 跟随系统** 三档；预设、点阵、圆角、字体与明暗相互独立。

开启「自定义外观」后，预设会锁定，可调整主题色、字体、点阵开关、点阵间距（8–40px）、点阵大小（0.5–4px）和圆角（2–18px）。当前应用到主工作台与独立监看；直播浮窗保持自己的五类样式，不跟随工作台换肤。

弹幕工作台跟随晨光 / 夜航主题；v1 不提供内置浮窗预览，样式调整直接在实际浮窗中查看，避免预览尺寸与真实窗口不一致。

外观保存在 `config.json` 的 `appearance` 段（配置 schema v3）；从旧版升级时会先生成 `config.v2.bak`，校验或写盘失败则保持原配置并进入只读安全模式。`localStorage` 仅作为静态预览和桌面后端未就绪时的回退缓存。

旧版外观会在首次启动时一次性导入配置，并在本地记录迁移完成标记，不会在后续启动反复覆盖。若配置只读，界面会保留本机外观草稿但禁用保存，避免把默认值写回覆盖原配置。

直播浮窗动效保存在 `config.legacy.json` 的 `overlay.motion`，不写入严格 schema 的 `config.json`；回滚或备份时必须把 `config.json` 与 `config.legacy.json` 成对处理。

### 升级与回滚

升级与回滚需要成对处理配置：

- v2 → v3 会同时生成 `config.v2.bak` 与 `config.legacy.v2.bak`（若原 sidecar 存在）。回滚时必须成对恢复这两个文件，不能只恢复 `config.json`。
- 当前 v3 若残留已移除字段（如旧 `hotkeys`）或旧凭证字段，启动时会先生成 `config.cleanup.bak`，再重写为严格 v3；备份不包含明文凭证。
- `config.legacy.json` 存在但无法解析时，程序进入只读安全模式并备份为 `config.legacy.bak`，不会用默认值重写登录态、TTS、过滤与 Mock 配置。

## 配置说明（config.json）

| 键 | 说明 |
|---|---|
| `room_id` | 上次连接的房间号 |
| `platform` | 上次使用的平台：`bilibili` / `douyin`；保存在 legacy sidecar |
| `sessdata_enc` | 可选。B 站登录凭证的 DPAPI 密文，保存在 `config.legacy.json`；不会进入 `config.json` 或前端。点应用右上角「登录」按钮扫码即可自动写入，无需手动编辑 |
| `douyin_cookie_enc` | 抖音登录 Cookie 的 DPAPI 密文，保存在 `config.legacy.json`，不会进入 `config.json` 或前端 |
| `tts.voice / rate / pitch / volume` | 音色与语速（如 `+10%`）/音调（如 `+0Hz`）/音量（如 `+0%`） |
| `read.*` | 五类消息开关、礼物最低价值、播报模板（`{user}` `{text}` 等占位符） |
| `filters.*` | 屏蔽词、去重秒数、最长字符数、单用户冷却、全局冷却 |
| `queue.max_size` | 朗读队列上限（默认 30，超出丢最旧） |
| `appearance.*` | 工作台外观：预设、主题色、点阵、圆角、字体与主题模式；严格白名单校验，仅影响主工作台与独立监看 |

界面里的改动会自动保存到 `config.json`。

### 抖音登录

切到「抖音」后点右上角「抖音登录」，ReadMe 会打开独立的抖音登录窗口。扫码成功后窗口自动关闭，Cookie 使用 Windows DPAPI 加密保存到 `config.legacy.json`；点击同一入口可退出登录。登录后会自动重连当前抖音房间一次。

## 常见问题

- **没有声音**：确认系统音量与输出设备；换一个音色试听；Edge TTS 需要联网（微软在线合成），断网时会失败并在底部提示
- **连接失败**：确认房间号正确且正在直播；未开播的房间无法连接
- **弹幕一直显示"未朗读"**：检查屏蔽词、冷却时间、对应类型开关、队列是否长期占满（高热度直播间建议调大 `global_cooldown`）
- **启动无反应**：查看 `logs\boot_error.log`；用 `run_debug.bat` 启动可看到控制台报错
- **弹幕用户名是星号（如 `月***`）**：这是匿名连接的正常现象。解决办法：点应用右上角「登录」→ 用 B 站手机 App 扫码 → 登录成功后**重新连接**直播间即可显示完整用户名。凭证以本机 DPAPI 密文保存在 `config.legacy.json`，想恢复匿名可在登录弹窗里点「退出登录」
- **日志与数据位置**：运行日志在 `logs\app.log`，启动异常在 `logs\boot_error.log`，本机历史在 `data\history.sqlite3`，手动导出在 `exports\history\`，音频缓存在 `cache\`。

## 已知限制

- 匿名连接时用户名打码、UID=0，按用户冷却只能按打码名判断；点右上角登录 B 站账号可恢复
- Edge TTS 依赖微软在线服务，断网即无法合成（会提示错误，不崩溃）
- 语音为在线合成，因此不是"完全离线"工具；如需离线可换 Piper/GPT-SoVITS（未集成）
- 高弹幕密度房间队列会积压并按最旧丢弃，属预期降级
- 超长弹幕（> `filters.max_len`，默认 80 字）会**截断后朗读**（保留前 80 字），这是防刷屏的保护性设计；纯表情/纯符号弹幕不朗读
- **音色语言需匹配文本**：英文等非中/日/韩音色无法朗读中文内容（微软服务对"英文音色读中文"直接返回空音频）。选中这类音色时界面会提示，中文弹幕会被自动跳过；朗读中文弹幕请在「音色」中选择中文音色（zh-CN-*）
- **系统加密不可用**：若 Windows DPAPI 不可用，凭证只能退化为 `plain1:` 可逆编码；设置页会常驻显示安全提示，请勿分享配置文件。解密失败的凭证会保持原密文、阻止登录并让配置进入只读模式，不覆盖原文件
- 历史场次只保存本机聚合统计，不保存弹幕正文、用户名或 UID；历史库 v5 增加抖音钻石流水字段，并保留 v4 的硬丢弃 / 规则过滤区分，v3 旧场次保留原丢弃总数并标记为旧口径。趋势只分析“平台 + 房间标识”确定的单一直播间，支持小时 / 本地日 / ISO 周自然周聚合，最多 366 天；少于 4 个可计算日不画折线，周视图少于 4 个非空周只作参考。缺少 `room_key` 的旧场次会显式阻断/标记，不静默混入其他房间。场次对比支持同房间任意已结束基准场；单基准保持独立契约，多基准最多 3 场、按选择顺序标记、不排名不聚合，并可导出独立的多场对比 JSON/CSV 报告；云同步尚未实现
- 复盘只比较同房间最近 20 场中通过门槛的本机记录；少于 8 场不生成名次，少于 12 场不展示 P25–P75。记录开始时间不是平台真实开播时间，复盘不代表观众规模、留存、平台营收或内容情绪
- 趋势读取前会等待本场聚合写入落盘；金额目前只按 B 站已知口径展示，其他平台在适配器定义金额字段前不会按 B 站规则折算
- B 站为主链路；抖音 v1 已接入公开弹幕、礼物/入场解析和账号登录（匿名连接下礼物推送可能受平台风控）。抖音礼物按 `单颗钻石 × 数量` 累计为本机钻石流水，不折人民币、不代表平台结算；平台未提供 SC/舰长等价能力，界面与报告明确显示“未提供”
- 动效 v1 的固定区（礼物 / SC / 舰长置顶置底）到期只做 ≤120ms 纯淡出，不占布局；滚动区支持独立入场/退场动效，并在约 ≥24 条/秒时自动做运行时简化

## 弹幕浮窗（窗口捕获）

左侧「弹幕工作台」页：

- **显示/穿透/置顶**：显示浮窗、鼠标穿透（穿透后不挡点击）、始终置顶
- **位置尺寸**：**整体缩放滑条（50%–400%）**、宽高、X/Y、一键居中/铺满右侧；非穿透模式下可直接拖动窗口、右下角缩放。工作台打开时几何数值会实时回读，修改位置/尺寸/缩放或其它外观项后自动应用，无需手动保存；缩放按比例影响实际浮窗的字号、间距与描边
- **多显示器**：可直接把浮窗拖到任意一块屏幕（支持负坐标/不同 DPI）；只有当窗口完全落到屏幕之间的空隙时，才会自动吸附到最近的屏幕（允许 40px 贴边），不会出现"拖过去就消失"
- **字体排版**：字体族、字号 10–96、字重、行高
- **颜色**：正文色、用户名色、背景色、背景不透明度、整体不透明度
- **描边/投影**：增强复杂背景下的可读性
- **内容**：显示用户名、用户名/正文最大长度、最多行数、条间距、停留时长、对齐
- **动效**：样式页「外观 / 动效」二级切换；五类消息可分别设置入场/退场方式（无/淡入/滑入/缩放）、时长、方向、位移、缩放与透明度；支持手动试跑；固定区到期做 ≤120ms 纯淡出，高密度滚动消息自动降为 ≤80ms 淡入/淡出
- **类型**：弹幕/礼物/醒目留言/上舰/入场 独立开关
- **礼物答谢**：置顶或置底、停留时长 2–600 秒、最多 1–6 条、最低礼物价值；同一用户同一礼物自动合并数量
- **主题预设**：经典/短视频/极简/高对比

> 工作台底部点「保存」后会保留当前页面，可继续微调（适合反复试字号/位置）。

在直播软件里添加「窗口捕获」（例如 OBS、Streamlabs 或直播伴侣），选择标题为 **ReadMe 浮窗** 的窗口即可获得透明弹幕层。

### 调试：模拟数据

「弹幕工作台 → 调试」：

**手动发送**：
- 消息类型：弹幕 / 礼物 / 醒目留言 / 上舰 / 入场 / 随机混合
- 用户名、内容可留空（自动填充示例）
- 三个按钮：发送 1 条 / 连发 10 条 / 弹幕风暴 30 条
- 「朗读这条消息」默认关闭；开启后批量注入会二次确认，并如实显示"实际朗读 M 条"（受冷却/去重影响）

**自动发送**（适合模拟不同体量直播间的弹幕密度）：
- 主开关：开启后按设定频率持续注入，关闭弹幕工作台也会继续运行
- 发送频率：200ms – 10s 可调
- 每次条数：1–10 条
- 数据类型：弹幕 / 礼物 / 醒目留言 / 上舰 / 入场 **可多选**（至少 1 类）
- 「朗读这些消息」默认关；开启后进入真实 TTS 管线
- 状态行实时显示：运行中 / 已发送条数 / 当前频率与类型

## 安全

- B 站与抖音登录凭证使用 Windows DPAPI 加密，保存在 `config.legacy.json`，不会写入前端或 `config.json`。
- 若 Windows DPAPI 不可用，程序会明确提示降级为 `plain1:` 可逆编码。请勿分享 `config.json`、`config.legacy.json` 或日志文件。
- 发现安全问题请通过 GitHub Security Advisories 私下报告，不要公开提交包含凭证的 issue。详见 [SECURITY.md](SECURITY.md)。
